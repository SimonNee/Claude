# C++ Orderbook — agentASM Evolution Project

## What this is

A limit orderbook implemented in C++, evolved across five iterations from a naive
correct baseline to a SIMD and atomics-optimised hot path. The orderbook is the
vehicle; the real subject is the process of getting there.

## Why it exists

The project exists to answer a question that interview whiteboards and LeetCode
cannot: **how do you move from a correct solution to a fast one, and how do you
know when to stop?**

The answer is not to write fast code first. It is to write correct code first,
measure it, understand where the material wants to go, and then apply precision
where precision is warranted. Not before.

## The philosophy

Every craft tradition arrives at the same principle independently.

The sculptor blocks out the form before working the detail. The painter composes
the canvas before mixing the final colours. The blacksmith draws the rough shape
before refining the edge. The builder lays the foundations before raising the
walls. Michelangelo did not start with David's eyes.

Software is no different. The structure must exist before you can refine it. The
measurement must exist before you can optimise it. You work coarse to fine,
moving up and down in resolution as the problem demands — not because a process
tells you to, but because that is how complex things get built.

This is more agile than Agile. It is just older.

## The iterations

| Iteration | What | Why |
|-----------|------|-----|
| 1 | Naive `std::map` baseline | Block out the form. Prove correctness. |
| 2 | Cache-friendly flat structures | agentDuality finds where the material wants to go. |
| 3 | RDTSC benchmarks + first ASM | Measure before touching. Apply precision to the confirmed hot path. |
| 4 | SIMD price level scan | Work at the instruction level where it earns its place. |
| 5 | Atomic snapshot publish | Control concurrency at the minimum necessary scope. |

Each iteration requires the previous one to be correct and understood before it
begins. No roofs before walls.

## The agents

**agentASM** — writes and reviews inline x86-64 assembly. Consulted only when
benchmarks have identified a specific hot path. It does not guess; it responds
to evidence.

**agentDuality** — analyses time and space trade-offs. Time and space are duals:
you can almost always trade one for the other. agentDuality's job is to find
where that trade is worth making before any code is changed.

Both agents follow the same discipline as the project: read the pitfalls first,
consult the phrasebook, work at the right resolution, document the reasoning.

## The data pipeline

Synthetic order data is generated by a KDB+/q script (`data/gen_orders.q`),
producing realistic price walks and skewed quantity distributions. The schema
contract between the generator and the C++ consumer is documented in
`data/schema.md`. Neither side changes without the other.

## Correctness is non-negotiable

The same 14 correctness tests run at every iteration. If they fail, the
iteration is not complete. Performance without correctness is not performance —
it is a fast wrong answer.
